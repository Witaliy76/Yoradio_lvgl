# Логотип загрузки и экран LVGL Boot — справка

> **Язык:** русский. English version: [`bootlogo.md`](bootlogo.md).

Файл рядом с `scr_boot.cpp`. Описан **экран LVGL Boot** (этап 5.4): ассет битмапа, как его поменять, настройки раскладки.

---

## 0. Зафиксированные решения

1. **Константы раскладки Boot** — один блок в начале `scr_boot.cpp` (`Boot layout — single source`).
2. **Полоска с бегунком** — только **индикментный** признак загрузки; не реальный прогресс и не determinate API.
3. **`onBootSignal()`** — **временная** заглушка; убрать или заменить, когда контракт boot будет приведён в порядок.
4. **Показ CPU во время Boot** — индикатор CPU **не показывается**, пока активен `isLvglBootActive()` (в `DspCore::loop()` RGB-панелей ST7701 / UEDX / AXS).
5. **`LV_LOG_LEVEL_INFO`** в `lv_conf.h` — **временная** отладка; после проверки **вернуть `LV_LOG_LEVEL_WARN`**.
6. **Позиция блока с лого** — **вся колонка** (лого + статус + бар) выравнивается **`LV_ALIGN_CENTER`** на экране Boot, затем сдвигается на **`kRootLiftY`** (см. §4). Речь не только об отдельной картинке по центру.
7. **Минимум ~3 с на Boot** — переход на Main после `DSP_START` ждёт `kLvglBootMinVisibleMs` с момента показа Boot (`lvgl_ui.cpp`), если сеть не заставила ждать дольше. Неблокирующе: `Display::_tryCompleteLvglPlayerHandoff()`. В AP Boot снимается сразу.
8. **Вертикальный ритм (зафиксировано, только отступы, 2026-03)** — принятые значения: **`kRootLiftY = -16`**, **`kGapLogoToStatus = 24`**, **`kGapStatusToBar = 38`**. Шрифты, геометрия/цвета/политика анимации индикатора и ассет лого без изменений.

## 2. Формат картинки

- **Имена и размер:** в комментариях конвертера — **имя проекта** (например `yoradio_240`), это **не** ширина. Реальный размер в коде: **170×149** (medium, `YORADIO_BOOTLOGO_MEDIUM_*`), **114×97** (small).
- **Кодирование:** RGB565 (`uint16_t` на пиксель), для вшитого массива **без RLE**.
- **LVGL 9:** статические дескрипторы `lv_image_dsc_t` используют `LV_COLOR_FORMAT_RGB565`, `magic = LV_IMAGE_HEADER_MAGIC` и `stride = width × 2`; дисплей явно настроен на RGB565 без перестановки байтов.
- **Инструмент:** [lcd-image-converter](https://github.com/riuson/lcd-image-converter) — пресет **Color R5G6B5**, вывод C-массива.

**PNG из LittleFS:** в текущей конфигурации не поддерживается: runtime-декодеры PNG/JPEG/SVG отключены. Boot использует статические C-дескрипторы и не зависит от LittleFS.

**Scale вместо второго файла:** в LVGL 9 `lv_image_set_scale(img, z)` использует **256 = 100%**, **128 ≈ 50%**, **77 ≈ 30%**. Чтобы масштабирование шло от центра: `lv_image_set_pivot(img, w/2, h/2)` в координатах исходной картинки. Минусы: нагрузка на отрисовку и возможное «мыло» по сравнению с отдельным битмапом.

## 3. Замена boot-лого — что обязательно поменять

Одного «положить файл в `assets/` и прописать имя» **недостаточно**. **Три места** должны соответствовать **реальной** ширине, высоте и **имени символа** массива пикселей:

| Шаг | Действие |
|-----|----------|
| 1. Файл `.c` | Добавить или заменить `.c` в `lvgl_ui/assets/`. Массив пикселей — **без `static`** (внешняя связь для линковки из `scr_boot.cpp`). Число элементов = **W × H** значений `uint16_t`. |
| 2. `bootlogo_assets.h` | `extern` + макросы **`YORADIO_BOOTLOGO_MEDIUM_*`** и/или **`SMALL_*`** = фактические пиксели из конвертера. |
| 3. `scr_boot.cpp` | Дескрипторы `s_boot_logo_dsc_medium` / `s_boot_logo_dsc_small` — синхронизировать `.data`, размеры и `data_size`. |

**Да, размеры обязательны.** Если `W`/`H` или `data_size` не совпадают с массивом, LVGL читает мимо буфера — артефакты или падение.

**Имя файла `.c`** можно менять как угодно (PlatformIO собирает все `.c` под `src/`). **Имя символа** в C (`image_data_*`) меняется — тогда обновляются `extern` в заголовке и поле `.data` в дескрипторе.

После правок — пересборка и проверка на железе.

## 4. Раскладка и стили

**Главная «ручка»:** константы в начале `scr_boot.cpp` (блок `Boot layout — single source`).

| Константа | Смысл |
|-----------|--------|
| `kRootLiftY` | Вертикальный сдвиг **всей** колонки относительно центра экрана (`lv_obj_align(..., 0, kRootLiftY)`); отрицательное — **вверх**. |
| `kStatusPadMul` | Поля по ширине подписи: `frame_padding * kStatusPadMul`. |
| `kGapLogoToStatus` | Зазор между лого и статусом в центральной колонке. |
| `kGapStatusToBar` | Зазор между статусом и полоской-индикатором в центральной колонке. |
| `kBarWidthPercent` | Ширина дорожки, % от ширины экрана. |
| `kBarHeight` | Высота дорожки (px). |
| `kShuttleWidthPercent` | Ширина бегунка, % от дорожки. |
| `kShuttleAnimMs` | Длительность **одного** прохода бегунка слева направо (мс), ease in-out; **без** обратного хода / ping-pong (`lv_anim_set_playback_time(..., 0)`). |

**Эталонные отступы (принято):** `kRootLiftY = -16`, `kGapLogoToStatus = 24`, `kGapStatusToBar = 38` — см. §0.8.

**Структура раскладки:** один центрированный flex-контейнер-колонка: `лого → спейсер → статус → спейсер → бар`.

**Шрифт статуса:** `LV_ACTIVE_PROFILE.font_small` — в профиле дисплея `../profiles/`.

**Внешний вид дорожки/бегунка:** `apply_track_style()` / `apply_shuttle_style()` в `scr_boot.cpp`.

## 5. Поведение

- **Историческая заметка об артефактах Boot → Main:** старый общий путь через `Arduino_Canvas` стабилизировали полноэкранным буфером и `full_refresh = 1`. Это не текущая топология 4848S040. Сейчас LVGL 9 использует один PSRAM draw-буфер 480×160 (153600 Б), `LV_DISPLAY_RENDER_MODE_PARTIAL` и синхронный CPU blit `DisplayPort → esp_lcd` в один физический PSRAM framebuffer 480×480. Старое наблюдение сохраняется как история миграции, а не как актуальная инструкция по диагностике.
- **Минимум на экране:** не меньше **3 с** до Main после `DSP_START`, если сеть была быстрой — см. §0.7.
- **Бегунок:** только indeterminate, не реальный прогресс.
- **`onBootSignal()`:** временная заглушка — §0.3.
- **Текст статуса:** `Display::loop()`, `bootScreenSetStatusUtf8`.
- **Потоки:** только **DspTask** для `lv_*` на Boot.
