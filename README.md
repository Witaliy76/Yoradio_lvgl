# YoRadio LVGL

YoRadio LVGL — Wi-Fi интернет-радио на ESP32-S3 с сенсорным квадратным дисплеем. Интерфейс построен на LVGL 9.5 и включает шесть основных страниц, а также отдельные экраны настройки Wi-Fi, быстрого доступа к избранным станциям и заставки.

Кроме экрана устройства есть Web UI: управление воспроизведением, список станций, настройки поведения и раздел Appearance — темы, фоны Main screen и обложка текущей станции. Для звука проект рассчитан на внешний I2S ЦАП или усилитель.

Проект основан на [e2002/yoradio](https://github.com/e2002/yoradio); текущий репозиторий — [Yoradio_lvgl](https://github.com/Witaliy76/Yoradio_lvgl).

> Публичная beta: `0.9.434m-r2-lvgl-beta.2`. Поддерживаемая плата: **ESP32-4848S040**.

## Дизайн и характер прибора

YoRadio задуман как самостоятельный музыкальный прибор и объект присутствия, а не как приложение, перенесённое на маленький экран. Музыка остаётся главным содержанием: интерфейс помогает слушать, не требует постоянного внимания и не конкурирует с воспроизведением.

Визуальный язык опирается на спокойный скандинавский hi-fi-подход и эстетику аналоговой аудиотехники: ясная типографика, спокойная композиция, сдержанные акценты и образы классических приборов. В продукте это видно, например, в Visual (индикация в духе Beocord) и в палитре Amber Hi-Fi для темы Custom. Устройство должно естественно находиться в интерьере и не выглядеть как смартфон или планшет.

Из этого следует практическое правило: основное состояние экрана — покой. Интерфейс не мигает, не показывает уведомлений и не требует реакции; движение появляется там, где оно осмысленно — в индикации уровня сигнала или в бегущей строке длинного названия. Экран построен как приборная композиция: технический статус сверху, объект прослушивания в центре, тихая техника и признаки жизни сигнала снизу.

Разные страницы несут разные роли: Main — прослушивание, Visual — атмосфера, Info — состояние прибора, Station — выбор, Weather — обстановка вокруг, Settings — функциональное управление. Ни одна из страниц не пытается стать универсальным меню и не дублирует остальные.

## Основные возможности

- Воспроизведение интернет-радиостанций: MP3, AAC, FLAC, OGG/Vorbis, Opus.
- Шестистраничный сенсорный интерфейс на LVGL 9.5: Info, Main, Visual, Station, Weather, Settings.
- Список станций с постраничной навигацией.
- Weather — текущая погода и прогноз (OpenWeatherMap) с устойчивым к сбоям DNS сетевым путём.
- Visual — приборная эмуляция классического индикатора уровня в духе винтажных Beocord.
- Preset Temporary — быстрый доступ к 8 сохранённым станциям.
- Analog Screensaver — аналоговые часы в режиме ожидания.
- Web UI — плеер, станции, настройки, Appearance, обновление прошивки.
- Темы Dark / Light / Custom, station artwork и отдельные фоны Main для каждой темы.
- Локализация интерфейса RU / EN / PL / SK (выбирается при сборке).
- AI Layer — необязательный тихий информационный слой поверх музыки.

### Visual

Visual — не произвольная декоративная анимация, а цифровая реконструкция поведения классического индикаторного механизма в духе винтажных приборов Beocord. Индикатор работает от фактического уровня декодированного аудиосигнала: два независимых канала по восемь сегментов со шкалой от −20 dB до +5 dB, где последние три сегмента — красная зона перегрузки.

Движение подчиняется приборной баллистике: быстрый подъём по сигналу, удержание достигнутого пика около 0,12 с и затем плавный спад с фиксированной скоростью. Уровень считается по среднему значению сигнала с ограниченной поправкой на текущую активность и добавкой на резкие транзиенты — благодаря этому шкала показывает «тело» музыки, а не только отдельные всплески.

> Реакция зависит от динамики самого аудиопотока. Если радиостанция передаёт сильно скомпрессированный звук с почти постоянным уровнем, индикатор будет двигаться в небольшом диапазоне. Это нормальное отражение фактического сигнала, а не неисправность Visual.

Индикация работает только во время проигрывания потока.

### Weather

Текущая погода, ощущаемая температура, ветер, влажность, давление, почасовой прогноз и прогноз на ближайшие дни. Данные берутся из OpenWeatherMap.

Сетевой путь погоды сделан устойчивым к сбоям разрешения имён. Если адрес сервиса не удалось получить или соединение не установилось, запрос повторяется — до трёх попыток на цикл, с последовательным перебором резолверов: сначала DNS, выданный роутером, затем публичные Cloudflare (1.1.1.1) и Quad9 (9.9.9.9). Уже опробованные адреса в рамках одного цикла не повторяются, а прогноз использует адрес, который только что сработал для текущих условий. Это заметно снижает вероятность потерять погоду при временном сбое DNS у роутера или провайдера.

## Дополнительные режимы

### Preset Temporary

Быстрый доступ к избранным станциям. Открывается свайпом вниз от верхнего края экрана и доступен ровно с четырёх страниц:

- Info;
- Main;
- Visual;
- Weather.

На Station и Settings этот жест Preset не открывает: там вертикальные и служебные жесты принадлежат самим страницам.

8 слотов: короткое нажатие запускает станцию, долгое — сохраняет текущую в слот. Экран закрывается примерно через 15 секунд бездействия и возвращает на ту страницу, с которой был вызван.

### Station Artwork

Автоматическое получение обложки из радиопотока пока не поддерживается: изображения назначаются станциям вручную. Обложка привязывается к текущей воспроизводимой станции, поэтому библиотеку можно собирать постепенно — включить станцию, загрузить для неё картинку, перейти к следующей.

Готовить файл заранее не нужно. Web UI принимает большинство распространённых форматов изображений, которые умеет декодировать браузер, после чего картинка автоматически центрируется, обрезается по принципу «cover», уменьшается до 120×120 и преобразуется во внутренний формат устройства. Подходящее изображение обычно проще всего взять с официального сайта или страницы радиостанции.

**Choose image** выбирает файл и показывает preview; **Upload to device** записывает готовое изображение на устройство; **Remove artwork** удаляет его.

### Color Theme и Custom Palette

Темы **Dark**, **Light** и **Custom** переключаются сразу и сохраняются. Dark и Light — встроенные заводские палитры.

Custom — не просто третий пресет, а полноценная настраиваемая тема. Её палитра описывается обычным текстовым файлом `theme_custom.txt`: одна запись `key=#RRGGBB` в строке, размер до 4096 байт, строки, начинающиеся с `#`, игнорируются как комментарии. Файл можно открыть в любом текстовом редакторе, изменить нужные цвета и загрузить в устройство. Кроме цветов есть числовые параметры — например `theme_dark` (`true` / `false`) для светлого или тёмного варианта Custom. Готовый пример со всеми ключами лежит в репозитории: [`src/src/lvgl_ui/theme/theme_custom.example.txt`](src/src/lvgl_ui/theme/theme_custom.example.txt), подробное описание ключей — в [`src/src/lvgl_ui/theme/THEME.md`](src/src/lvgl_ui/theme/THEME.md).

**Upload & Apply** загружает файл и сразу применяет палитру; **Remove custom palette** удаляет пользовательский файл и возвращает встроенную палитру **Amber Hi-Fi**. Изменения касаются только темы Custom — Dark и Light остаются заводскими.

### Main Screen Backgrounds

Фон меняется только на экране Main — остальные страницы его не используют. Для Dark, Light и Custom предусмотрены три независимых слота, поэтому фон каждой темы настраивается отдельно и не влияет на другие.

Как и с обложками, подходят распространённые форматы, которые декодирует браузер: изображение автоматически центрируется, масштабируется с обрезкой по краям и преобразуется под экран 480×480. Загрузка фона не переключает активную тему — картинка просто закрепляется за выбранным слотом.

**Choose image** только готовит preview; **Upload to device** записывает слот; **Remove image** удаляет только выбранный слот. Отсутствие файла — нормальное состояние: Main просто рисуется на цвете темы.

## Отличия от оригинального проекта

Форк развивает YoRadio как проект с полноценным сенсорным интерфейсом на LVGL и отдельными аппаратными профилями поддерживаемых плат. По сравнению с исходным [e2002/yoradio](https://github.com/e2002/yoradio):

- новый UI на LVGL 8.3 вместо legacy Canvas-экранов на поддерживаемой плате;
- шестистраничное кольцо навигации и отдельные режимы Boot / Wi-Fi / Preset / Screensaver;
- Visual как приборная эмуляция индикатора уровня с собственной баллистикой, а не декоративная шкала;
- Web UI Appearance: темы, редактируемая палитра Custom, независимые фоны Main и station artwork;
- устойчивый сетевой путь погоды с повторными попытками и перебором резолверов;
- согласованный сетевой и TLS-профиль библиотек для стабильного воспроизведения тяжёлых потоков и HTTPS-запросов во время проигрывания;
- файловая система LittleFS;
- compile-time локализация RU / EN / PL / SK;
- optional AI Layer как тихий информационный слой в нижней строке Main;
- акцент на внешнем I2S ЦАП как основном варианте звука для повседневного использования.

Другие board-профили могут оставаться в исходниках, но в публичную beta входят только проверенные сценарии для ESP32-4848S040.

## AI Layer

AI Layer — необязательный тихий слой поверх музыки. Он не является ассистентом, не ведёт диалог и не стремится заполнять экран текстом: молчание для него — нормальное состояние. Для работы нужны OpenAI-compatible API, ключ, модель и prompt; без них YoRadio остаётся обычным интернет-радио.

Результат появляется ненавязчиво: короткая строка в нижней информационной зоне экрана Main, под технической строкой параметров потока. Слой не перекрывает панель управления, громкость и метаданные воспроизведения, не открывает окон и не превращает экран в чат. Если сказать нечего, строка остаётся пустой — на других страницах AI не выводится вообще.

Подробнее:

- [AI Layer в YoRadio](readme_ai_layer_rus.md) — назначение и философия слоя;
- [как устроен prompt](readme_ai_prompt_explained_rus.md) — правила языка, тона и формата вывода.

### Замечание для сборки из исходников

Прошивка собирается с заменённым набором системных библиотек ESP-IDF, и это не косметическая деталь — от него зависят два практических качества устройства.

Настроенный профиль **LwIP / esp_netif** нужен для устойчивого длительного воспроизведения тяжёлых сетевых потоков, включая FLAC и станции с высоким битрейтом: он снижает вероятность сетевых остановок и проблем с буферизацией. Полное отсутствие разрывов при этом не гарантируется — многое зависит от самой станции и качества связи.

Согласованный профиль **mbedTLS (Profile B)** нужен не «просто для HTTPS». AI Layer выполняет TLS-запросы одновременно с работающим LVGL и аудиодекодером, а штатному mbedTLS при такой нагрузке могло не хватить достаточно крупного непрерывного блока внутренней памяти — handshake завершался ошибкой выделения памяти. Profile B снижает эти требования, поэтому HTTPS-запрос проходит во время воспроизведения; дополнительно работает защитная проверка, которая пропускает запрос, если свободного непрерывного блока всё же слишком мало. Именно поэтому архивы нельзя заменять произвольными версиями по отдельности — набор согласован целиком.

- Для source build требуется полный KnownGood-набор из `library!/esp32s3_5_5_2__3_3_6_ai_tls_profile_b_FULL_WORKING_20260603_221741/`. В нём находятся 10 согласованных архивов LwIP, esp_netif, HTTP и mbedTLS/TLS; ранний каталог только с `liblwip.a` и `libesp_netif.a` для текущей beta недостаточен.
- Набор предназначен для PIOArduino `55.03.36`, Arduino-ESP32 `3.3.6` и пакета `framework-arduinoespressif32-libs` `5.5.0+sha.f56bea3d1f` (ESP-IDF 5.5.2). Архивы копируются с заменой в `framework-arduinoespressif32-libs/esp32s3/lib/`, после чего нужно перезапустить PlatformIO, выполнить clean и собрать проект заново.
- Файлы набора: `libesp_http_client.a`, `libesp_netif.a`, `libesp-tls.a`, `libhttp_parser.a`, `liblwip.a`, `libmbedcrypto.a`, `libmbedtls.a`, `libmbedtls_2.a`, `libmbedx509.a`, `libtcp_transport.a`.
- Целевой каталог: Windows — `%USERPROFILE%\.platformio\packages\framework-arduinoespressif32-libs\esp32s3\lib\`; Linux/macOS — `~/.platformio/packages/framework-arduinoespressif32-libs/esp32s3/lib/`.
- После переустановки или обновления framework package замену нужно повторить.
- Эта операция нужна только при сборке из исходников. Готовые файлы из `build_bin/` уже собираются с нужным набором библиотек.
- Язык интерфейса задаётся в `src/myoptions.h` через `L10N_LANGUAGE`: `RU`, `EN`, `PL` или `SK`. Переключения языка во время работы нет.
- Исходники поддерживают RU, EN, PL и SK. Готовые бинарники beta.2 (`RU` / `EN` / `PL` / `SK`) и инструкция прошивки — в [`build_bin/4848S040/`](build_bin/4848S040/) и [`build_bin/4848S040/README.md`](build_bin/4848S040/README.md).
