# YoRadio LVGL

YoRadio LVGL — Wi-Fi интернет-радио на ESP32-S3 с сенсорным квадратным дисплеем. Интерфейс построен на LVGL 9.5 и включает шесть основных страниц, а также отдельные экраны настройки Wi-Fi, быстрого доступа к избранным станциям и заставки.

Кроме экрана устройства есть Web UI: управление воспроизведением, список станций, настройки поведения и раздел Appearance — темы, фоны Main screen, обложка текущей станции и необязательный пользовательский текстовый TTF. Для звука проект рассчитан на внешний I2S ЦАП или усилитель.

Проект основан на [e2002/yoradio](https://github.com/e2002/yoradio); текущий репозиторий — [Yoradio_lvgl](https://github.com/Witaliy76/Yoradio_lvgl).

> **Публичная версия:** `0.9.434m-r2-lvgl-beta.2`
> **Текущие исходники:** `0.9.434m-r2-lvgl-beta.2-s6.4`
> **Проверенная плата:** ESP32-4848S040

## Дизайн и характер прибора

YoRadio задуман как самостоятельный музыкальный прибор и объект присутствия, а не как приложение, перенесённое на маленький экран. Музыка остаётся главным содержанием: интерфейс помогает слушать, не требует постоянного внимания и не конкурирует с воспроизведением.

Визуальный язык опирается на спокойный скандинавский hi-fi-подход и эстетику аналоговой аудиотехники: ясная типографика, спокойная композиция, сдержанные акценты и образы классических приборов. В продукте это видно, например, в Visual (индикация в духе Beocord) и в палитре Amber Hi-Fi для темы Custom. Устройство должно естественно находиться в интерьере и не выглядеть как смартфон или планшет.

Из этого следует практическое правило: основное состояние экрана — покой. Интерфейс не мигает, не показывает уведомлений и не требует реакции; движение появляется там, где оно осмысленно — в индикации уровня сигнала или в бегущей строке длинного названия. Экран построен как приборная композиция: технический статус сверху, объект прослушивания в центре, тихая техника и признаки жизни сигнала снизу.

Разные страницы несут разные роли: Main — прослушивание, Visual — атмосфера, Info — состояние прибора, Station — выбор, Weather — обстановка вокруг, Settings — функциональное управление. Ни одна из страниц не пытается стать универсальным меню и не дублирует остальные.

## Основные возможности

- Воспроизведение интернет-радиостанций: MP3, AAC, FLAC, OGG/Vorbis, Opus.
- Шестистраничный сенсорный интерфейс на LVGL 9.5: Info, Main, Visual, Station, Weather, Settings.
- Список станций с постраничной навигацией.
- Weather — текущая погода и прогноз (OpenWeatherMap) с устойчивым к сбоям DNS сетевым путём.
- Visual — приборная эмуляция классического индикатора уровня в духе винтажных Beocord.
- Preset Temporary — быстрый доступ к 8 сохранённым станциям.
- Analog Screensaver — аналоговые часы в режиме ожидания.
- Web UI — плеер, станции, настройки, Appearance, обновление прошивки.
- Темы Dark / Light / Custom, station artwork и отдельные фоны Main для каждой темы.
- Локализация интерфейса RU / EN / PL / SK (выбирается при сборке).
- Масштабируемые TTF-шрифты и иконки Tabler с поддержкой RU / EN / PL / SK; необязательная замена обычного текста своим TTF через Appearance.
- AI Layer — необязательный тихий информационный слой поверх музыки.

## История изменений

### 03.09.2026 — 0.9.434m-r2-lvgl-beta.2-s6.4

Завершена финальная приёмка платы ESP32-4848S040.

**Стабилизация RGB-вывода.** Устранён давний дефект, при котором повторное сохранение пресета или смена темы могли оставить экран чёрным, а затем вернуть картинку со сдвигом по горизонтали. Причиной оказалась политика драйвера RGB-панели: проектная сборка `libesp_lcd` отключала автоматический перезапуск сканирования по VSYNC. Теперь используется штатная сборка ESP-IDF 5.5.5 с `RESTART_IN_VSYNC=ON`, а сборочная проверка не даёт случайно вернуть устаревшую подмену библиотеки. Чёрный экран и остаточный сдвиг на устройстве больше не воспроизводятся.

**Быстрое переключение тем.** Раньше каждое нажатие на строку Theme целиком выполняло тяжёлую операцию — переинициализацию темы LVGL, обновление стилей всего интерфейса, перерисовку страниц и запись выбора в файл. При быстрой серии переключений это приводило к срабатыванию watchdog и перезагрузке. Теперь запросы объединяются: применяется только последний выбор, промежуточные отбрасываются, запись в файл происходит один раз. Строка Theme сразу показывает выбранное значение, итоговый фон соответствует итоговой теме.

**Чистка диагностики.** Из исходников удалены восемь семейств отладочных макросов и временных счётчиков, оставшихся от закрытых расследований (около 1070 строк). Служебный вывод в консоль стал заметно тише. Диагностика PCM/VU и отладка касаний, AI-слоя и стека LVGL сохранены — они понадобятся для будущих доработок.

### Visual

Visual — не произвольная декоративная анимация, а цифровая реконструкция поведения классического индикаторного механизма в духе винтажных приборов Beocord. Индикатор работает от фактического уровня декодированного аудиосигнала: два независимых канала по восемь сегментов со шкалой от −20 dB до +5 dB, где последние три сегмента — красная зона перегрузки.

Движение подчиняется приборной баллистике: быстрый подъём по сигналу, удержание достигнутого пика около 0,12 с и затем плавный спад с фиксированной скоростью. Уровень считается по среднему значению сигнала с ограниченной поправкой на текущую активность и добавкой на резкие транзиенты — благодаря этому шкала показывает «тело» музыки, а не только отдельные всплески.

> Реакция зависит от динамики самого аудиопотока. Если радиостанция передаёт сильно скомпрессированный звук с почти постоянным уровнем, индикатор будет двигаться в небольшом диапазоне. Это нормальное отражение фактического сигнала, а не неисправность Visual.

Индикация работает только во время проигрывания потока.

### Weather

Текущая погода, ощущаемая температура, ветер, влажность, давление, почасовой прогноз и прогноз на ближайшие дни. Данные берутся из OpenWeatherMap.

Если адрес сервиса не удалось получить или соединение не установилось, запрос повторяется — до трёх попыток на цикл, с последовательным перебором резолверов: сначала DNS, выданный роутером, затем публичные Cloudflare (1.1.1.1) и Quad9 (9.9.9.9). ### TIMERS и Deep Sleep

Строка **TIMERS** открывает вкладки **RADIO** и **DEEP SLEEP** с четырьмя независимыми сохранёнными пресетами. У каждого события есть свой ON/OFF и отдельные кнопки `−/+` для часов (0–24) и минут (0–59). Короткое нажатие меняет выбранное поле на единицу без переноса и зацикливания; удержание включает повтор с ускорением. OFF сохраняет выставленное значение, но блокирует его кнопки. ON при `00:00` показывает `SET INTERVAL` и не позволяет запустить событие. Активный countdown является runtime-only и после обычной перезагрузки не восстанавливается. Одновременно может работать только один план — Radio либо Deep Sleep; для перехода к другому сначала отмените текущий.

Во вкладке **RADIO** интервалы `STOP RADIO AFTER` и `START RADIO AFTER` независимо отсчитываются от одного нажатия `START TIMER`; доступны Stop-only, Start-only и оба события. Остановка идёт штатной командой плеера, запуск — текущей сохранённой станции. Если нужное состояние уже достигнуто, событие становится безопасным no-op. Когда оба события ON, Start должен быть строго позже Stop: при конфликте UI показывает `START MUST BE LATER THAN STOP` и блокирует кнопку запуска, не меняя выставленные значения автоматически. Status indicator `SLEEP 10m` показывает Radio Stop, `DEEP SLEEP 10m` — задержку до Deep Sleep; Radio Start в status line не выводится.

Во вкладке **DEEP SLEEP** событие `DEEP SLEEP AFTER` задаёт задержку до управляемого shutdown, а `WAKE AFTER SLEEP` — отдельный RTC-интервал, который начинается только после фактического входа в Deep Sleep. Поэтому Sleep `5 MIN` и Wake `3 MIN` — корректная комбинация: устройство заснёт через 5 минут и проснётся примерно через 3 минуты после входа. При Sleep OFF и Wake ON строка показывает `WAKE AFTER NEXT SLEEP`: countdown не создаётся, а пресет применяется к следующему `SLEEP NOW` или команде `deepsleep`. Wake OFF явно отключает RTC timer wake, не отключая настроенный GPIO wake. Wake ON с `00:00` требует сначала задать интервал. Остановка плеера, flush состояния, выключение дисплея и вход в сон выполняются единым managed pipeline.

Строки `STOPS/STARTS/SLEEP/WAKE AT ...` — только подсказка по локальным часам. При отсутствии синхронизации выводятся `--:--` и `CLOCK NOT SYNCED`, но относительные monotonic-таймеры продолжают работать. Абсолютное расписание `HH:MM` не реализовано.

| Telnet / Serial | Действие |
|---|---|
| `sleeptimer N` / `sleeptimer 0` | Поставить / отменить только runtime Radio Stop; пресет не меняется |
| `playtimer N` / `playtimer 0` | Поставить / отменить только runtime Radio Start; пресет не меняется |
| `deepsleep` | Немедленный managed Deep Sleep с сохранённым `WAKE AFTER SLEEP`; может отменить Radio plan |
| `deepsleep N` / `deepsleep 0` | Поставить / отменить задержку входа в Deep Sleep; сохранённый wake-пресет не меняется |
| `sleep N` | Совместимость со старым CLI: немедленный managed Deep Sleep с разовым wake через `N` минут |
| `sleep N M` | Совместимость со старым CLI: managed Deep Sleep через `M` минут с разовым wake через `N` минут после входа |

Новые команды разбираются одинаково через telnet и Serial даже без Wi-Fi; допустимый диапазон — 0…1499 минут. Разовый wake-интервал, переданный через совместимую старую команду `sleep`, не перезаписывает сохранённый пресет. Deep Sleep countdown отображается как `DEEP SLEEP Nm`; перед фактическим входом Serial monitor сообщает RTC-интервал и локальное расчётное время пробуждения.

Пробуждение от тачскрина GT911 в Deep Sleep не поддерживается. Пробуждение по настроенному `WAKE_PIN` поддерживается; для ESP32-4848S040 источник EXT0 — штатная кнопка **BOOT** (GPIO0, активный LOW). RTC timer и BOOT могут быть разрешены одновременно, побеждает первый источник. После любого Deep Sleep wake GPIO0 рано возвращается из RTC IO в digital GPIO до инициализации RGB-панели. Reset и переподключение питания остаются запасными способами запуска. Подробности — в [руководстве по ESP32-4848S040](README_4848S040.md#пробуждение-из-deep-sleep).

### Station Artwork

Автоматическое получение обложки из радиопотока пока не поддерживается: изображения назначаются станциям вручную. Обложка привязывается к текущей воспроизводимой станции, поэтому библиотеку можно собирать постепенно — включить станцию, загрузить для неё картинку, перейти к следующей.

Готовить файл заранее не нужно. Web UI принимает большинство распространённых форматов изображений, которые умеет декодировать браузер, после чего картинка автоматически центрируется, обрезается по принципу «cover», уменьшается до 120×120 и преобразуется во внутренний формат устройства. Подходящее изображение обычно проще всего взять с официального сайта или страницы радиостанции.

**Choose image** выбирает файл и показывает preview; **Upload to device** записывает готовое изображение на устройство; **Remove artwork** удаляет его.

### Color Theme и Custom Palette

Темы **Dark**, **Light** и **Custom** переключаются сразу и сохраняются. Dark и Light — встроенные заводские палитры.

Custom — не просто третий пресет, а полноценная настраиваемая тема. Её палитра описывается обычным текстовым файлом `theme_custom.txt`: одна запись `key=#RRGGBB` в строке, размер до 4096 байт, строки, начинающиеся с `#`, игнорируются как комментарии. Файл можно открыть в любом текстовом редакторе, изменить нужные цвета и загрузить в устройство. Кроме цветов есть числовые параметры — например `theme_dark` (`true` / `false`) для светлого или тёмного варианта Custom. Готовый пример со всеми ключами лежит в репозитории: [`src/src/lvgl_ui/theme/theme_custom.example.txt`](src/src/lvgl_ui/theme/theme_custom.example.txt), подробное описание ключей — в [`src/src/lvgl_ui/theme/THEME.md`](src/src/lvgl_ui/theme/THEME.md).

**Upload & Apply** загружает файл и сразу применяет палитру; **Remove custom palette** удаляет пользовательский файл и возвращает встроенную палитру **Amber Hi-Fi**. Изменения касаются только темы Custom — Dark и Light остаются заводскими.

### Main Screen Backgrounds

Фон меняется только на экране Main — остальные страницы его не используют. Для Dark, Light и Custom предусмотрены три независимых слота, поэтому фон каждой темы настраивается отдельно и не влияет на другие.

Подходят распространённые форматы, которые декодирует браузер. Картинка сохраняет пропорции: длинная сторона ограничивается 1280 px без обрезки, растяжения и увеличения. Браузер сохраняет JPEG (качество 0.90) в пользовательский слот выбранной темы. Загрузка фона не переключает активную тему.

**Choose image** только готовит preview; **Upload to device** записывает пользовательский JPEG; **Remove image** удаляет только его. Если пользовательского файла нет, используется заводской JPEG темы; если нет и его — цвет темы.

### Пользовательский текстовый шрифт

Обычный текст интерфейса можно заменить своим файлом **TTF** (не OTF и не иконки). Загрузка и удаление — в Web UI → Appearance. Максимум **512 КиБ**. После успешной загрузки нужна **перезагрузка**; живой шрифт сам не меняется, автоматической перезагрузки нет. В Appearance есть необязательная кнопка **Reboot now**.

Если пользовательского файла нет или он отклонён, остаётся заводской Montserrat. Иконки Tabler этим не затрагиваются. В репозитории есть необязательные примеры Play и PT Sans (`fonts/samples/`) — они не входят в прошивку и не копируются в LittleFS при сборке.

## Отличия от оригинального проекта

Форк развивает YoRadio как проект с полноценным сенсорным интерфейсом на LVGL и отдельными аппаратными профилями поддерживаемых плат. По сравнению с исходным [e2002/yoradio](https://github.com/e2002/yoradio):

- новый UI на LVGL 9.5 вместо legacy Canvas-экранов на поддерживаемой плате;
- масштабируемые встроенные TTF (TinyTTF) вместо лестницы compiled-шрифтов на каждый размер;
- шестистраничное кольцо навигации и отдельные режимы Boot / Wi-Fi / Preset / Screensaver;
- Visual как приборная эмуляция индикатора уровня с собственной баллистикой, а не декоративная шкала;
- Web UI Appearance: темы, редактируемая палитра Custom, независимые фоны Main, station artwork и необязательный пользовательский текстовый TTF;
- устойчивый сетевой путь погоды с повторными попытками и перебором резолверов;
- согласованный сетевой и TLS-профиль библиотек для стабильного воспроизведения тяжёлых потоков и HTTPS-запросов во время проигрывания;
- файловая система LittleFS;
- compile-time локализация RU / EN / PL / SK;
- optional AI Layer как тихий информационный слой в нижней строке Main;
- акцент на внешнем I2S ЦАП как основном варианте звука для повседневного использования.

Другие board-профили могут оставаться в исходниках, но в публичную beta входят только проверенные сценарии для ESP32-4848S040.

## AI Layer

AI Layer — необязательный тихий слой поверх музыки. Он не является ассистентом, не ведёт диалог и не стремится заполнять экран текстом: молчание для него — нормальное состояние. Для работы нужны OpenAI-compatible API, ключ, модель и prompt; без них YoRadio остаётся обычным интернет-радио.

Результат появляется ненавязчиво: короткая строка в нижней информационной зоне экрана Main, под технической строкой параметров потока. Слой не перекрывает панель управления, громкость и метаданные воспроизведения, не открывает окон и не превращает экран в чат. Если сказать нечего, строка остаётся пустой — на других страницах AI не выводится вообще.

Подробнее:

- [AI Layer в YoRadio](readme_ai_layer_rus.md) — назначение и философия слоя;
- [как устроен prompt](readme_ai_prompt_explained_rus.md) — правила языка, тона и формата вывода.

## Ограничения beta

- Публично поддерживается только ESP32-4848S040.
- Язык интерфейса (RU / EN / PL / SK) выбирается при компиляции; runtime-переключения нет.
- Выход из Deep Sleep — по настроенному `WAKE_PIN` (на ESP32-4848S040 это BOOT / GPIO0), RTC-таймеру `WAKE AFTER SLEEP`, либо Reset/питанию. Тачскрин источником пробуждения не является.
- Web UI работает в локальной сети, без HTTPS.
- Для полноценного звука рекомендуется внешний I2S ЦАП.

### Замечание для сборки из исходников

Порядок сборки:

1. Скачайте или обновите YoRadio.
2. Откройте проект в PlatformIO.
3. Нажмите **Build**.

Больше ничего не требуется. Вручную заменять архивы ESP-IDF внутри `.platformio` **не нужно** — прежняя инструкция по копированию `.a`-файлов в `framework-arduinoespressif32-libs` больше неактуальна и не поддерживается.

PlatformIO сам загружает закреплённый в [`platformio.ini`](platformio.ini) пакет — PIOArduino `55.03.311` (Arduino-ESP32 `3.3.11`, ESP-IDF `5.5.5`). Общий пакет PlatformIO при этом остаётся нетронутым: YoRadio ничего в нём не меняет и не перезаписывает.

Свои правки YoRadio держит у себя в репозитории, в каталоге `library!/esp-idf-5.5.5/s3/`. Там лежат семь архивов ESP-IDF, пересобранных из штатных исходников Espressif с конфигурацией YoRadio, и `manifest.txt` с полной провенанс-информацией (версии, коммиты, SHA256, список изменённых параметров). Это **не** обычная Arduino-библиотека: файлы оттуда не нужно никуда копировать, устанавливать или подключать по отдельности.

Всё остальное делает сборочный помощник `yoradio_build.py`. PlatformIO запускает его автоматически на каждой сборке (`extra_scripts` в `platformio.ini`) — **вручную его запускать не нужно**. Помощник определяет целевой чип, проверяет версии платформы, ядра и ESP-IDF, сверяет SHA256 всех семи архивов и только после этого подключает их через путь поиска компоновщика, попутно включая необходимые набору опции компоновки mbedTLS.

Проверка устроена по принципу «всё или ничего»: совпали все семь архивов — используется оптимизированный профиль YoRadio целиком; не совпало хоть что-то — не используется ничего. В последнем случае сборка не прерывается: помощник печатает предупреждение и собирает проект на полностью штатном наборе библиотек ESP-IDF. Это штатный запасной режим, а не ошибка, но и характеристик оптимизированного профиля он не даёт — прошивка получится с обычными сетевыми и TLS-настройками ESP-IDF.

Зачем этот набор нужен — от него зависят три практических качества устройства.

Настроенный профиль **LwIP** нужен для устойчивого длительного воспроизведения тяжёлых сетевых потоков, включая FLAC и станции с высоким битрейтом: он снижает вероятность сетевых остановок и проблем с буферизацией. Полное отсутствие разрывов при этом не гарантируется — многое зависит от самой станции и качества связи.

Настроенный профиль **mbedTLS** нужен не «просто для HTTPS». AI Layer выполняет TLS-запросы одновременно с работающим LVGL и аудиодекодером, а штатному mbedTLS при такой нагрузке могло не хватить достаточно крупного непрерывного блока внутренней памяти — handshake завершался ошибкой выделения памяти. Режим динамических буферов снижает эти требования, поэтому HTTPS-запрос проходит во время воспроизведения; дополнительно работает защитная проверка, которая пропускает запрос, если свободного непрерывного блока всё же слишком мало. Именно поэтому архивы нельзя заменять произвольными версиями по отдельности — набор согласован целиком вместе со своими опциями компоновки.

Пересобранный **esp_lcd** нужен RGB-дисплею: в нём отключён автоматический перезапуск RGB-панели по каждому VSYNC, вместо него ресинхронизацией управляет слой Display самой YoRadio. На штатном `esp_lcd` это поведение вернуть нельзя.

- ESP32-S3 и ESP32-P4 — независимые профили. Собственный набор архивов сейчас принят только для S3; сборка под P4 полностью использует штатные библиотеки ESP-IDF и архивы S3 не наследует.
- Сборка под Windows проверена на устройстве. Сборка с локальным набором под Linux/macOS пока не проверялась — это отложенная задача на переносимость, а не известная проблема прошивки.
- Всё вышеописанное относится только к сборке из исходников. Готовые файлы из `build_bin/` уже собраны с нужным набором библиотек.
- Язык интерфейса задаётся в `src/myoptions.h` через `L10N_LANGUAGE`: `RU`, `EN`, `PL` или `SK`. Переключения языка во время работы нет.
- Обычная сборка встраивает два готовых TTF из [`src/src/lvgl_ui/fonts/`](src/src/lvgl_ui/fonts/) (`readme_fonts.md`) в Flash приложения. Генерировать шрифты вручную, ставить fontTools и заливать factory TTF через LittleFS не нужно. Необязательный пользовательский текст загружается отдельно через Web UI на устройство (`/fonts/user.ttf`); примеры в [`fonts/samples/`](fonts/samples/) в прошивку не входят.
- Исходники поддерживают RU, EN, PL и SK. Готовые бинарники публичной beta.2 (`RU` / `EN` / `PL` / `SK`) и инструкция прошивки — в [`build_bin/4848S040/`](build_bin/4848S040/) и [`build_bin/4848S040/README.md`](build_bin/4848S040/README.md).
